# BridgeKit — Quality Scorecard

Scored under The Elite Software Master Prompt v1.1, §17. Every score names its evidence; a score without evidence would be a Fail. This file is updated in the same change as the work it scores.

**State at v0.1.0: total 85.4/100 — the release bar (total ≥ 85, no dimension below 3, no Fail) is met for the local gate.** Two recorded waivers remain (Performance and Scalability measurements — both are "no measurement taken" waivers on a tool whose workload is kilobyte-scale text). All behaviour BridgeKit itself owns is Verified locally: generation and `verify` are pure text/byte functions, exercised by golden tests over the real kits' headers and by a `verify` run against SignKit's real shipped `sign_kit.dll` (7/7, exit 0, run with both the debug and release binaries). What remains Partially Verified is only the release workflow's first run (it fires at the v0.1.0 tag) and the generated bindings' behaviour inside a consuming app, which is the consumer's gate by design.

## What moves the score

1. First generated binding compiled and field-run inside a real consumer (raises Correctness; anything found is fixed forward with a regression test or a grammar note).
2. `verify` wired into the kits' own CI (ROADMAP 2) so the real-DLL evidence becomes per-kit and automated instead of one manual SignKit run (raises Test evidence and Correctness).
3. The v0.1.0 tag's release-workflow run producing `BridgeKit-v0.1.0-x64.zip` with the three expected entries (closes the one Partially Verified workflow row in PARITY).
