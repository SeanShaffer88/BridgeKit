# BridgeKit — agent notes

- BridgeKit is a **CLI tool, not a DLL** (the GoldenKit shape, not the WatchKit shape): a `[lib]` core (`header`, `gen_cs`, `gen_rs`, `pe`) plus one thin `[[bin]]` in `src/main.rs`. Do not re-add a cdylib/FFI surface — the crate was scaffolded as a DLL and deliberately reshaped; `Cargo.toml` carries the note.
- **Never guess a type mapping.** The header grammar in `src/header.rs` is pinned to what the collection's headers actually use (surveyed against NotifyKit, WatchKit, SignKit). An unknown type is a hard error naming the token — including sneaky ones like `size_t`, which must NOT be treated as a handle (handle names require an initial capital). If a kit grows a real new type, extend `classify` + the mapping tables in both generators + a fixture in the same change.
- **The generated C# class is `public`, always.** A non-public `[DllImport]` class compiles and then fails at call/test time with inaccessible-member errors — that false failure burned a smoke-test round in this collection. `cs_class_is_always_public` pins it.
- **Owned vs borrowed strings are different wrappers.** `char *` results are caller-owned: the wrapper copies, then frees through the header's *own* declared `<prefix>_free_string` (looked up by name suffix — never assumed) in a `finally` / after copying. `const char *` results (`_version`, `_last_error`) are borrowed: copy, never free. A header with `char *` results but no `_free_string` is a hard error in both generators — no improvised wrapper.
- String *returns* stay `IntPtr` / raw pointers on the raw import in both languages. Declaring an owned `char *` return as a managed string frees it with the wrong allocator. The `_string` wrappers are the only string view.
- Golden files under `tests/golden/` are generated by running the tool on the fixtures in `tests/fixtures/` (trimmed copies of the real shipped headers, with attribution comments). Regenerate them only by running the tool, review the diff like code, and never hand-edit a golden to match changed output.
- `verify` fails (exit 1) only on *missing* exports, each named. Extra exports are warnings. The PE reader (`src/pe.rs`) is pure byte parsing, bounds-checked, no panics — its tests build a minimal PE32+ byte-wise in `tests/common/mod.rs`; keep that builder honest (real export directory layout, sorted name table).
- Zero dependencies; edition 2021 / rust-version 1.80, as per the family.
- Release shape: one zip `BridgeKit-<tag>-x64.zip` with `bridgekit.exe` + `README.md` + `LICENSE` (adapted from the canonical DLL `release.yml`; the deviation is recorded in `docs/PARITY.md`). Binaries are unsigned.
- Gate: WinDevKit `tools/gate.sh` (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate.
